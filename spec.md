# Спецификация: In-Memory URL Shortener (Python Core)

## Обзор
Документ описывает функциональные требования для модуля сокращения ссылок на Python. Реализация представляет собой чистую бизнес-логику (без веб-слоя), использующую оперативную память для хранения состояния. Разработка ведется по принципам TDD (Test-Driven Development).

---

## 1. Что строим (In Scope)
*   **Класс `URLShortener`**: Основной интерфейс для взаимодействия.
*   **Генерация короткого кода**: Создание уникальной строки (alias) для длинного URL.
*   **Разрешение (resolve) короткого кода**: Получение оригинального URL по короткому коду.
*   **In-memory хранилище**: Использование словаря Python (`dict`) для маппинга `short_code -> original_url`.
*   **Базовая валидация URL**: Проверка входящего URL на соответствие базовому формату.
*   **Модульные тесты**: Покрытие логики с использованием `pytest`.

---

## 2. Чего НЕ строим (Out of Scope)
*   **REST API / Web слой**: Никаких эндпоинтов (Flask, FastAPI, Django), HTTP-запросов и ответов.
*   **Базы данных**: Никакого SQLAlchemy, Redis, PostgreSQL и т.д. Только `dict` в оперативной памяти.
*   **Пользовательские алиасы**: Пользователь не может задать свой короткий код (например, `my-link`). Генерация только автоматическая.
*   **Аналитика и статистика**: Счетчик кликов, сохранение IP-адресов, user-agentов, дат создания.
*   **Срок годности (TTL) ссылок**: Ссылки живут столько, сколько живет объект класса в памяти.
*   **Защита от спама / Rate limiting**.
*   **Многопоточность / Асинхронность**: Предполагается синхронное использование в однопоточном контексте тестов.

## 4. Acceptance Criteria (AC)

### AC-1: Успешное сокращение валидного URL
*   **Given** экземпляр `URLShortener` и валидный URL `https://google.com`
*   **When** вызывается метод `shorten(url)`
*   **Then** возвращается строка длиной от 6 до 8 символов, состоящая только из символов `[0-9a-zA-Z]`
*   **And** при вызове `resolve()` с полученным кодом возвращается `https://google.com`

### AC-2: Идемпотентность сокращения (REQUIRED)
*   **Given** экземпляр `URLShortener`
*   **When** дважды вызывается `shorten()` с одним и тем же URL
*   **Then** возвращается один и тот же короткий код (экономия памяти)
*   **Note**: Для `URLShortener` вызов `shorten()` с идентичным URL должен возвращать тот же код без создания новой записи; `_counter` при этом НЕ инкрементируется

### AC-3: Успешное разрешение (resolve) существующего кода
*   **Given** экземпляр `URLShortener`, в котором уже сохранен маппинг `abc123` -> `https://ya.ru`
*   **When** вызывается `resolve('abc123')`
*   **Then** возвращается строка `https://ya.ru`

### AC-4: Обработка несуществующего кода
*   **Given** экземпляр `URLShortener`
*   **When** вызывается `resolve('nonexistent')`
*   **Then** возвращается `None`

### AC-5: Отклонение невалидного URL
*   **Given** экземпляр `URLShortener`
*   **When** вызывается `shorten()` с невалидным значением (например, `not-a-url`, `ftp://example.com`, пустая строка)
*   **Then** выбрасывается исключение `ValueError`

## 5. Edge Cases (Граничные случаи)

При написании тестов (`pytest`) необходимо обязательно покрыть следующие сценарии:

1.  **Отсутствие протокола**: `www.google.com` или просто `google.com` — **должны быть отклонены** (считаем невалидными без `http://` или `https://`).
2.  **Пустой ввод**: `""` (пустая строка), `None` — должны приводить к `ValueError` (или `TypeError` для `None`).
3.  **Пробелы**: `" https://google.com "` или `"https://google.com/q=hello world"` — поведение на усмотрение разработчика, но в AC должно быть зафиксировано (рекомендация: обрезать `.strip()` для URL и отклонять URL с пробелами внутри пути/запроса).
4.  **Очень длинный URL** (например, 2000+ символов с параметрами GET) — хранилище (`dict`) должно его переварить, генерация короткого кода не должна зависеть от длины оригинального URL.
5.  **URL со спецсимволами**: `https://example.com/path?param=1&foo=bar#anchor` — должен сохраняться и возвращаться **посимвольно идентично** без потерь или двойного экранирования.
6.  **Регистрозависимость короткого кода**: `resolve('AbC123')` и `resolve('abc123')` — **не должны** считаться одним и тем же кодом (Base62 чувствителен к регистру).
7.  **Коллизия генератора (если используется хэширование вместо счетчика)**: Если алгоритм генерирует код, который уже есть в `dict`, он должен перегенерировать его, а не перезаписать старый URL (поэтому счетчик предпочтительнее).
8.  **Попытка передать в `resolve` невалидные типы**: Например, целое число `resolve(123)` — должно выбрасывать `TypeError`.
